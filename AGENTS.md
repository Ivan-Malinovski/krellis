# Krellis

Krellis ("KDE + Trellis") is a port of DanFessler/trellis (infinite-canvas "desktop": camera over a tiled layout, springs, docking, minimap) to KDE Plasma 6 / KWin Wayland, MIT licensed and public at github.com/Ivan-Malinovski/krellis (branch `master`, release `v0.0.2`). It was formerly called kwin-trellis. The goal behind it: Ivan liked Hyprland but found it not mouse-friendly enough, and wanted that plus Trellis in KDE. The whole code base is AI-written ("vibe coded"); the README says so.

Clean-room: follow the semantics of the Trellis TypeScript, do not copy its code (noncommercial license). Reference sources are read-only at `~/dev/trellis_kde/trellis/packages/core/src/` on Ivan's machine; they are not part of this repo.

User-facing docs are `README.md` (install, keys, settings, safety) and `CHANGELOG.md`. Keep them in step when behaviour, shortcuts or settings change. This file is the developer guide.

## Layout

- `core/`: pure C++20 model library `krellis_core` (no Qt GUI, no KWin). tree, document, spatial (focus layout, framing, docking targets), resize (push drags), motion (springs, tweens, easing), builder, navigator (camera state machine).
- `effect/`: the KWin effect (`KrellisEffect` coordinator, one `KrellisCanvas` per output, input, painting, QML overlays).
- `config/`: `krellis_config`, the one reader/writer of `krellisrc` (see Settings GUI).
- `kcm/`: the System Settings module (`kcm_krellis`).
- `tests/`: QtTest, one executable per core module (`ctest`).
- `scenarios/`: nested-KWin test scripts (about 100 files, with `.rc` seeds and small Qt clients).
- `tools/`: `nested.sh` (nested harness, exports `KRELLIS_ROOT`; scenarios use it instead of absolute paths), `shot`, `preview.sh`, `live.sh`, and Ivan's dev installer `install.sh` / `uninstall.sh`.
- `install.sh` (repo root): the public installer (see Installing).
- `spikes/hello/`: minimal out-of-tree KWin effect used to prove the toolchain.
- `third_party/`: ECM, Vulkan headers and the KWin 6.7 source on Ivan's machine only (gitignored, a workaround for missing dev packages). A normal checkout has none of it and uses system packages.

## Build and test

Core only (fast, no KWin needed):

    cmake -S . -B build-core -G Ninja -DCMAKE_BUILD_TYPE=Debug
    cmake --build build-core && ctest --test-dir build-core --output-on-failure

KWin effect (with system dev packages; see README Requirements):

    cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DKRELLIS_BUILD_EFFECT=ON

On Ivan's machine the KWin dev files are not installed system-wide, so add `PATH=$HOME/.local/bin:$PATH` and
`-DCMAKE_PREFIX_PATH=$PWD/third_party/ecm-prefix -DVulkan_INCLUDE_DIR=$PWD/third_party/vulkan-headers/include`.

## Testing effects safely

Never load experimental effects into the live session. Use the nested compositor:

    tools/nested.sh <plugin-root> <effect-id,...> <scenario-script> [width height]

Typical unattended run (results in `$NEST_WORK/out/log.txt`; redirect output to a file and never pipe it to `tail`):

    NEST_OUTPUTS=2 KWIN_WAYLAND_NO_PERMISSION_CHECKS=1 NEST_BACKEND=virtual NEST_SOCKET=krellis-test-X NEST_WORK=/tmp/krellis-X \
      tools/nested.sh build/root krellis scenarios/<name>.sh 1280 800 >out 2>&1 </dev/null

Set `NEST_BACKEND=virtual` to render off-screen: no window opens on Ivan's desktop, so automated runs cannot steal focus (verified with `basic.sh`; always use this for unattended tests, and a distinct `NEST_SOCKET`/`NEST_WORK` when his preview is running). Only `tools/preview.sh` should use the default windowed backend.

It runs its own D-Bus session and throwaway `XDG_CONFIG_HOME`, socket `krellis-nest`, work dir `/tmp/krellis-nest`. Screenshots inside it: `spectacle -b -f -n -o`.

**Running many scenarios: `tools/scenarios.sh`.** `tools/scenarios.sh tabs pin` runs just those; with no names it runs all of `scenarios/` (`-j N` runs N at once, default 6; `-k` keeps passing work dirs; `-t S` sets the per-scenario timeout). It gives every run its own socket and work dir, switches core dumps off (a crashing nested KWin otherwise raises crash-watch notifications), and prints `ok|FAIL|-  name pass= fail=`; `-` means the scenario only prints state. A run fails on a `FAIL` line, a KWin crash, or a timeout. Failing runs keep their logs (the path is printed). Per-scenario setup: `scenarios/<name>.rc` seeds `krellisrc` (the nested default is only `glide=true` plus a few quiet switches, which many scenarios need to differ from), `scenarios/<name>.env` is sourced to override the seed (`NEST_KRELLISRC=`) or set `EXPECT=`, and a `NEST_OUTPUTS=2` mention in the script's header gives it two outputs. Workflow: while developing a feature run only its scenarios (about 30 s); run the whole suite (about 7 min at `-j 2`/`-j 3`) before a commit. Do not go above `-j 3`: timing-sensitive scenarios (`pin`, `tabs`, `scratch`, `key-output`) fail from load alone at 6, and pass when run singly. Known failures on clean HEAD, not regressions: `drawer-stack` and `drawer-tabs` (2 hover checks each), and `drop-anim`, `flyto`, `previewsize` (checked 2026-10-22 against a HEAD build).

## KWin facts (6.7.5)

- Effects use the 3-arg `prePaintWindow` and `paintWindow` with `WindowPaintData`; `isActive()` must return true.
- `Window::inputTransformation()` is translate-only; scaled input needs a custom `InputEventFilter`.
- Out-of-tree effects are ABI-locked to the exact KWin version; rebuild after KWin upgrades.
- Qt Widgets must be in `find_package` for `KWin::kwin`.
- Verified in the nested KWin: `data += QPointF` / `data *= QVector2D` scale from the window's top-left; off-screen `moveResize` is honoured; D-Bus interface is `org.kde.kwin.KWin.KrellisEffect` on `/Krellis`.
- New windows append at the root's end seam (`seamTarget` + `applyDockTarget`) so columns share 1/n equally.

## Gotchas

- Lambdas that outlive their scope must capture `axis` etc. by value (a dangling capture broke `dragBoundary`).
- `DragHost::lastRects()` must return a stable snapshot (`m_lastRects`, rebuilt by `refreshRects()` at frame boundaries): `DragSession`'s ctor holds iterators across calls, and a map rebuilt per call is UB (wrong lifted size).
- Model `Node`s are immutable (`shared_ptr<const Node>`); every edit returns a new tree.

## Current implementation

Full desktop-demo parity is not complete; real-hardware input, fractional scaling and unusual monitor layouts remain unverified. `KrellisEffect` coordinates independent `KrellisCanvas` instances per output. `effect/surface_input.cpp` implements scaled Wayland input and popup transforms; `effect/view_rules.cpp`, `bar.qml`, and `tiles.qml` implement rules, framing names and small icon tiles. `effect/persistence.cpp` and `session_store.cpp` provide session storage backed by pure model rebinding in `core/session.cpp`.

Animations: camera spring 210/29; layout 460 ms cubic Hermite with velocity retained on interruption; drag landing 240 ms; appear 220 ms; dock hide 300 ms; restore 380 ms; close 180 ms. Keep every visible transition animated.

## Rules

Follow `~/AGENTS.md`: no pushes, no commits unless asked, no secrets.

- Never `pkill -f <pattern>` from a tool command: the pattern matches the shell itself (exit 144). Use `pkill alacritty` or exact names.
- Never call `Navigator::endGesture()` from the frame loop: a pinch/drag only ends via `finishGesture()` (an early `endGesture` made `finishGesture` a no-op).

## Work area (2026-10-20)

- For each output, use KWin `clientArea(MaximizeArea, output)` in logical coordinates; reserve the Krellis bar inside that rectangle. Do not use global `WorkArea`: it can combine unrelated output struts.
- Poll client areas every 100 ms because panel strut updates need not change output geometry. Window geometry and bar/minimap placement glide for 460 ms with easeOutQuint, including updates during an existing flight.
- `scenarios/area.sh` builds `scenarios/panel.cpp` against installed Qt6Gui and LayerShellQtInterface and tests real top/bottom layer-shell exclusive zones and removal. Run only in the nested harness.
- Reject `LayerShellV1Window` explicitly when managing windows: layer-shell surfaces can report a normal window type and otherwise become tiles. Use QObject `inherits`: this internal subclass does not export `staticMetaObject`, so `qobject_cast` makes the effect fail to load.
- Ivan chose independent canvases. `effect/multicanvas.cpp` owns the effect coordinator; the existing behavior in `krellis_effect.cpp` is now `KrellisCanvas` (QObject + NavigationHost + DragHost). Only the coordinator is an effect-chain participant and input filter owner. Canvas methods must not forward pre/post-paint down the chain; the coordinator does so once. Window painting is dispatched to one owner.
- `Window::moveResize` changes its reported output when a camera places a neighbour across an output edge. Guard these writes with `m_applyingRest`; do not interpret them as user transfers. Explicit KWin output changes are deferred and transferred, while drag transfer uses the release pointer.
- Paint regions are DEVICE coordinates in this KWin version. Clip with `RenderViewport::mapToDeviceCoordinatesAligned`, not raw logical output geometry. Transfer flights may cross outputs; ordinary canvas windows may not.
- `NEST_OUTPUTS=2 tools/nested.sh ... scenarios/monitors.sh 1280 800` starts two outputs. Scenario control adds `selectOutput`, `dumpOutput`, `moveToOutput`; window indices are local to the selected canvas. Output disable migrates windows; reconnect starts an empty canvas.
- Nested Wayland output scale changes are deliberately ignored by KWin. Rotation is supported and tested; fractional output scaling is still unverified. No live-session testing has been performed.

## Scaled input and popups

- `effect/surface_input.cpp` maps the painted frame back through the resting frame and then `Window::inputTransformation()` into Wayland surface coordinates. Do not just scale event x/y: frame origins, client/buffer offsets, popup offsets and output origins all matter.
- Pointer hit-testing uses the visual stacking order and output ownership, not KWin's resting geometry. A client grab owns subsequent motion/releases, including outside the output; gestures/UI release focus and block app events. Keep press/release pairs balanced, including popup-dismissal clicks. Physical move/resize must pass through: KWin's InteractiveMoveResize filter is AFTER Effects.
- Popups never enter a document. Their painting and input inherit the owning parent's transform recursively; they use 220 ms appear and 180 ms close. `visualRect` is shared by paint and input, and closed popup refs live in `m_closing`.
- `scenarios/scaled.sh` builds `input-client.cpp` with installed Qt6Widgets and inspects actual Wayland deliveries. Its coordinate tolerance is 0.3 px because `dump` prints normal window rectangles to 0.1 px. It asserts the test is genuinely scaled and that the popup is scaled too. `core/input_geometry.h` has independent inverse/child-rectangle tests.
- Real hardware routing, decoration drags and pointer constraints remain unverified. Never load into the live compositor to check them.

## View policies and saved layouts

- Save opens the bar's editable framing name. QML receives key events through `OffscreenQuickScene::forwardKeyEvent`; suppress paired client releases after Return/Escape closes it.
- Rules use Qt INI nested keys in `$XDG_CONFIG_HOME/krellisrc`: `[ViewRules]` followed by `app-id\placement=stage`, `app-id\scaling=inert`, `app-id\minWidth=800`, etc. Placement is side/stage/floating; scaling is interactive/inert/none. Permissions: allowSide, allowStage, allowFloating; singleton and closable are booleans. Reload via D-Bus `reloadRules`. Invalid files must not partially apply.
- `toggleDock` (Meta+Shift+D) docks a float beside the stage or restores its remembered viewport-normalized floating rectangle. Respect placement permissions. Tiny panels show native app icons; their opacity uses spring 210/29 and visual stacking must prevent input through covering windows.
- Persistence is schema 1 JSON in `$XDG_STATE_HOME/krellis/session.json` (QStandardPaths GenericStateLocation), atomically written with owner-only permissions. Store structure, ratios, floats, hidden restore anchors and navigation per output. Never serialize window titles or process IDs.
- Ivan chose unique matches only: identify windows by desktop app ID/resource class plus role, and restore only if the identity occurs exactly once among both saved and live windows. Leave duplicates fresh. Match globally across outputs; output identity uses manufacturer/model/serial with connector fallback.
- Startup restores after a 750 ms quiet window and may retry late apps until user interaction. Pending unique matches block automatic overwrite. Corrupt/unsupported state stays untouched and disables writing. Preserve the last nonempty state during logout teardown.
- Saved structural IDs can collide with fresh panel IDs. `rebindSession` renames colliding structures and remaps navigation/hidden anchors, preserving noncolliding structures. Restore anchors may refer to splits, not just stages/panels.
- Harness isolates XDG_STATE_HOME. `NEST_SESSION_FILE` seeds state before startup. Persistence scenarios run save then restore with the saved `out/session.json`; `persist-monitors.sh` runs twice with NEST_OUTPUTS=2. Never seed from Ivan's personal state.

- Hidden panels have no layout rectangle. `applyRest` must skip model-hidden panels, including before native minimize during session restoration. Moving them to an empty rest rect produces a later Wayland configure commit that changes native output ownership after the synchronous geometry guard ends. Two-output persistence tests cover this regression.

## Native resize and interrupted flights (2026-10-20)

- Replacement flights must capture `visualRect` plus opacity before mutating the model or dropping an existing flight. Close holds the deleted window and minimize-visible reference until its captured fade completes. `interrupt.sh` covers reversals and close during glide/hide.
- `native_resize.cpp` handles real KWin resize signals. Pointer deltas are logical screen distances, applied to the initial painted edges; do not multiply by the existing paint scale. Native requested geometry can jump to a client minimum and is unsuitable as the visual delta.
- Resize preview pins the camera; split edits use `dragBoundary` and floating edits use normalized geometry. Session writing skips active previews. Cancel restores the saved document, accept remembers floating geometry, unload cancels native grabs before baseline restoration.
- `resize.sh` checks actual native stepped signals and commit/cancel, zoomed boundary deltas, scaled floats, opposite corners and rule-reload cancellation. `resize-stage.sh` repeats it with a stage policy; a seeded root split containing a stage-wrapped panel additionally covers transparent ancestor traversal. The new lifecycle branch checks unload during native resize. None establishes physical input feel or full desktop parity.
- `tools/preview.sh` provides an isolated interactive desktop with temporary state. Never use it concurrently with another nested harness (same socket). `KRELLIS_PREVIEW_SMOKE=1` exits after producing a screenshot.

## Rendering and native decoration input (2026-10-20)

- Always set screen-level `PAINT_SCREEN_WITH_TRANSFORMED_WINDOWS` before KWin prepares scene damage. Per-window `setTransformed()` alone leaves partial surface damage in native coordinates. Current implementation chooses full repaint for correctness.
- `QHoverEvent(type, scenePos, globalPos, oldPos)` takes LOCAL scenePos first. Keep a painted-decoration hover target, refresh hover on press, and synchronize `input()->pointer()->decoration()` to the painted hit. Wrong coordinates change `mouseGravity()` and turn title centres into resize corners.
- A decoration grab must receive its release even during a native move/resize and must bypass its own canvas drag-inertness. Otherwise the move stays active and the following click can target the previous window. Use native interactive anchors for move start/step.
- `decorations.sh` uses a real Wayland fake-input fixture restricted to task-owned `krellis-test-*` sockets. Build `krellis_paint_probe` explicitly for real-frame pixel checks; the probe never requests repaints. Scoped `KWIN_WAYLAND_NO_PERMISSION_CHECKS=1` is needed only for this nested test, never change the live compositor.
- Screenshot capture renders a new scene and cannot establish idle partial-repaint correctness. The paint probe checks real frame buffers, including output/texture transforms.
- `tools/nested.sh` honors an optional `NEST_SOCKET` and refuses occupied sockets. Keep `NEST_WORK` distinct per run. Atomically stage plugins to avoid truncating a mapped binary during a rebuild.

## Installing and trying it on the live desktop (2026-10-20)

- **Two installers.** The public one is `./install.sh` in the repo root (`--prefix`, `--no-kcm`, `--enable`, `--uninstall`; builds in `build-release/`, honours `DESTDIR`, `CMAKE_ARGS`, `BUILD_DIR`; with `DESTDIR` set it skips every D-Bus/kwriteconfig action; `--uninstall` follows `install_manifest.txt`). Tested only as a staged `DESTDIR` install. The notes below are about Ivan's dev installer `tools/install.sh`.
- `tools/install.sh` builds in `build-live/` and runs `sudo cmake --install --prefix /usr`, putting `krellis_<stamp>.so` in `/usr/lib/qt6/plugins/kwin/effects/plugins/` (older `krellis*.so` are removed). Every install uses a fresh plugin id (`-DKRELLIS_ID`; also the .so name and the `qrc:/<id>/` prefix) because KWin never re-reads a plugin file it has already mapped, so reusing `krellis.so` kept the old code running until a logout. `tools/live.sh on` unloads whatever Krellis is loaded and loads the newest installed id; `status` compares the running `version` D-Bus stamp with the installed file. The harness keeps the default id `krellis`. KWin only searches the system Qt plugin path (`/usr/lib/qt6/plugins`); a `~/.local` install is not found. ECM's own plugin dir resolves to `lib/plugins` here, so `effect/CMakeLists.txt` uses `KRELLIS_PLUGIN_DIR` (`lib/qt6/plugins`). The installed library has no RPATH.
- Installing does not enable it (`EnabledByDefault` false). `tools/live.sh on|off|status` loads/unloads it through `/Effects` and writes nothing to kwinrc, so a logout or KWin restart clears it. `tools/uninstall.sh` removes the files.
- Emergency exit: global shortcut Meta+Alt+Escape ("Krellis: Turn Off", D-Bus `turnOff`) unloads the effect; `scenarios/turnoff.sh` shows windows return to native geometry. The ABI is locked to KWin 6.7.5, so reinstall after every KWin upgrade, and never enable the effect permanently across an upgrade without rebuilding.
- Do not run either `install.sh`, `live.sh on` or any `sudo` from an agent session unprompted; Ivan runs them (`! tools/install.sh`). **Standing procedure (Ivan, 2026-10-28):** when a change is ready for the live desktop, ask Ivan whether to install, load and enable it. When he confirms (or says "install"), do all of it in one go: install through the `sudo`-to-`pkexec` wrapper, then `tools/live.sh on`, then `tools/live.sh status` to check the stamps match. Never stop after the install and wait to be told to load; an installed but unloaded build is useless to him. A crash of the effect would take down every Wayland app, including the agent's terminal.

## Bar, shortcuts and drag sizing (2026-10-20)

- The bottom bar is **off by default** (Plasma's panel covers most of it) and reserves no space unless on. Meta+Alt+B toggles it (`toggleBar`), Meta+Alt+M the minimap (`toggleMap`), Meta+Alt+S starts saving a named view (`saveView`; the bar floats over the windows just while naming). Scenarios that need the bar (`bar`, `area`, `map`, `names`) call `toggleBar` first; `bar-optional.sh` covers the default.
- Lifting a window for a drag shares its space among all siblings in proportion (`removePanel(..., keepProportions)`); closing/hiding keeps the upstream "next sibling absorbs it" rule. Dropping back into the same shape restores the original weights exactly (`sameShape` in `core/drag.cpp`). `scenarios/redrop.sh` guards this. vibetiles also tiles windows; unload it (`qdbus6 org.kde.KWin /Scripting org.kde.kwin.Scripting.unloadScript vibetiles89`) before trying Krellis live.
- `lifecycle.sh` needs socket `krellis-nest`. Always set `NEST_BACKEND=virtual` for unattended runs; the default backend opens a window on the desktop.

## Edge resize and real drag preview (2026-10-20)

- Real edge presses on tiled windows did nothing: KWin extends a decorated window's input region outward by `decoration()->resizeOnlyBorders()` (into the tile gap), but `KrellisEffect::surfaceHit` only tested the frame. It now does a second pass over windows with their resize-only borders added (only when no window body is under the pointer; a float's band is tried in the stacking pass, so it also wins over windows beneath it). Scenario `edge-resize.sh` (real pointer events) asserts it.
- During a drag, `applyRest()` no longer returns early: while a session previews a drop, every window except the lifted one is `moveResize`d to its previewed target (`restRect(panel, world)`), so clients redraw at the real size instead of being stretched. Cancel/commit restores via the normal rest layout. Scenario `previewsize.sh`.
- `decorations.sh` needs both effects: `nested.sh build/root krellis,krellis_paint_probe ...`.
- Round-trip "drag under another window and back" is width-stable in the model (`roundTripsUnderAndBackKeepWidths` in `tests/test_drag.cpp`, 12 variants x 4 cycles, equal starting weights). The shrinking-left-window report is NOT reproduced yet; suspects: unequal weights, min-size handling, or interference from the vibetiles KWin script.

## No stretched contents (2026-10-20)

Ivan's "left window keeps shrinking" and the ugly drag preview were the same thing: `paintWindow` scales by `shown/frame` per axis, so any window drawn at a rect with a different aspect than its frame (tweens, the drag card, previews while clients lag) had stretched glyphs. Sizing in the model was right all along. `KrellisCanvas::visualRect` now returns the largest aspect-preserving rect (top-left anchored) in the normal unzoomed view; it deliberately keeps per-axis fitting for zoomed views, live divider drags, floats and clamped (min/max rule) windows. `dump` rows end with `drawn WxH`; `previewsize.sh` asserts drawn aspect == frame aspect during a drag.

## Real-size animation and native maximize (2026-10-20)

- While `m_tween` runs, `prePaintScreen` calls `applyRest(true)` every tick so clients really resize through the animation (frame size = tweened rect size); one final `applyRest()` when it ends. The aspect-fit in `visualRect` then has nothing to correct. The earlier version jumped the frame to its final size and shrank the drawn rect to that aspect, so windows popped small at the top right and grew back. `scenarios/jank.sh` guards it.
- A native maximize (title-bar double click, maximize button) on a tiled, non-float window is undone and turned into `toggleMaximize` for its panel (deferred with a zero timer). `scenarios/maximize.sh`.

## Two monitors, maximize and cross-output drags (2026-10-20)

Ivan runs two outputs (DP-2 3440x1440 landscape, HDMI-A-1 1440x2560 portrait to its right), so multi-output paths are the live path, not an edge case.

- Zooming a canvas onto one panel (panel maximize) makes `applyRest` place every other tile outside its output, and KWin then reports `outputChanged` for windows that now sit on the neighbour. `KrellisCanvas::placedByUs(w)` (each `Tracked` remembers the frame `applyRest` last asked for) lets `watchOutput` ignore those changes, both at signal time and again in the deferred handler. Only a change we did not cause transfers a window. `scenarios/maximize2.sh` (`NEST_OUTPUTS=2`) maximizes and restores and asserts every window stays on output 0.
- A KWin-driven title-bar drag that leaves its output is handed live to the canvas under the pointer: `KrellisCanvas::m_handoff` (set in `syncOutputs`) cancels the source session, `transfer`s the window, and `adoptDrag` starts a fresh session on the destination, grabbing the new tile by the middle of its title bar so the lifted card follows the pointer. The destination shows the drop slot and real-size reflow preview, and the drop commits there; Escape still counts as a cancel because the original start geometry is carried over. `scenarios/cross-drag.sh` drives it with real pointer events.
- `monitors.sh` ends with kscreen-doctor rotate/hotplug steps addressed to `WL-1`, which exists only with the windowed nested backend; under `NEST_BACKEND=virtual` it stops there (everything before passes). `monitors.sh` and `persist-monitors.sh` now call `toggleBar` first because the bar is off by default (one global toggle, not per output).

## Floats versus the desktop example (2026-10-20)

Re-reading `examples/desktop/src` (App.tsx, desktop.ts, AppWindow.tsx): the demo mounts `<Workspace floating="stage">` with an empty `<Stage>` as the desktop, every app type has `placement="float"`, and `launch` opens windows as stage floats cascaded over the desktop. Tiling is the secondary mode: dragging a window past the stage edge docks it beside the desktop, the green button / "Dock Beside Desktop" calls `toggleDock`, and "Maximize" (frame the panel) is offered only for docked windows. Floats are stage-relative (they follow the camera and zoom with the desktop).

The effect only has viewport-fixed Overlay floats (`floatingLayer()` returns Overlay, `floatWorld` returns nothing). A tiled window can therefore never be dragged into a float; only Meta+Shift+D or a `placement=floating` rule makes one, and an existing float re-docks when released within the overlay edge band. Matching the demo means a Stage-as-desktop mode: `floatingLayer()` = Stage, an empty Stage root, `floatWorld`/`floatScreen` for stage floats, new windows opening as stage floats, and stage floats in persistence, resize and painting. Not built; Shift-drag floats, floating-first mode and drawers (below) cover the need differently.

## Shift-drag floats (2026-10-20)

First float affordance (option 2; the Stage-as-desktop mode is option 1 and will live alongside it): holding **Shift** while dragging a window by its title bar floats it where the card is dropped, and stops an existing float from docking at the screen edge. `DragSession::setForceFloat` (core) overrides the target with Float while the pointer is on screen; `KrellisCanvas::moveDrag` feeds it from `m_shiftHeld`, updated from every pointer motion event (`PointerMotionEvent::modifiers`) in `KrellisEffect::handleMotion`, so the modifier is re-read on each step, including after a cross-output handoff. Shift pressed without moving takes effect on the next motion. `simForceFloat(1|0|-1)` D-Bus slot stands in for the key in tests. `scenarios/float-drag.sh`.

## Float edge and corner snap (2026-10-20)

Ported from vibetiles' `edgeDropTargetRect` (`~/dev/trellis_kde/vibetiles/kwinscript/contents/ui/main.qml`). `DragSession::snapZone()` (core/drag.cpp): when the drop target is an **overlay Float** and the pointer is within `SnapEdgePx` (24) of a viewport edge, the float lands as that half; with one horizontal and one vertical side within `SnapCornerPx` (120) it lands as that quarter. `floatRect` returns the zone, and `updateSlot` draws it as the translucent slot (dump line `SNAP x,y wxh`). Only reachable while the target is Float: with Shift held, or an existing float moved over empty space away from the outer frame band. Without Shift, the viewport edge is the original's outer **frame band** (`frameDropTarget`), which docks the window across the whole edge of the layout; that already is the edge-drop for tiles. `scenarios/float-snap.sh`.

Obstacle fill (added later, from vibetiles): floats under the zone are not covered when there is room. `clearOf` shrinks the zone around them, keeping the piece that holds the pointer; an edge may grow past its half toward the screen, a corner stays inside its quarter. If the result is under half the zone in either direction (a sliver) the plain half or quarter wins and the floats are overlapped. `scenarios/float-fill.sh`.

## Floating-first / tiling-first modes (2026-10-20)

`[General] floatFirst` in `~/.config/krellisrc` (default false = tiling-first). Toggle: Meta+Alt+F, D-Bus `toggleFloatFirst`, `setFloatFirst(bool)`, `floatFirst()`; the setter persists to krellisrc and updates every canvas (`KrellisEffect::m_floatFirst`, mirrored into each `KrellisCanvas`, loaded at the top of the `KrellisEffect` ctor).
- New windows: a per-app `[ViewRules]` `placement` wins (`ViewRules::placementSet`); otherwise float-first opens a cascaded float (`0.2+0.025k, 0.15+0.035k, 0.6x0.65`, k = floats % 6) and tiling-first keeps the old Side placement.

## No content blink during glides (2026-10-20)

A client must never be asked for its FINAL size while the drawn rect is still animating: its contents lay out at the final size and are squashed into the shrinking or growing rect for a frame (the "blink"). Rules now: `applyRest()` always follows `m_tween` (layout glides: maximize, dock, drop, rule change, hide/restore) so requests equal the drawn size; `restRect` and `visualRect` use `sizingCamera()` (the animated camera while it glides, the target otherwise; target during a drag session or native resize); `prePaintScreen` re-requests each frame while tweening or springing and once more at rest (`m_steppingResize`). `endDrag` begins the tween BEFORE `relayout(false)` so the first request is already the drawn size. Scenarios: `zoom-blink.sh` (Ctrl+wheel) and `maximize-blink.sh` sample frame vs drawn width.

**Throttle (2026-10-20, late).** Following the drawn size every frame made heavy clients (Brave) re-lay-out at dozens of intermediate sizes, which felt stuttery next to a manual border drag. While a glide runs (`applyRest(true)` from `prePaintScreen`), a client is given its next size only once it has landed the previous request (frame within 1px of `Tracked::requested`) or has sat on it for `SteppingPatienceMs` (120). The final `applyRest()` at rest is unconditional. Not tuned against a real Brave yet.

## Scratchpad: a layer over the canvas (2026-10-21)

- **What it is.** Scratch windows (marked at run time with Meta+Shift+G / the minimap's "Mark active", D-Bus `toggleScratchMarkActive`, or flagged by `scratchpad=true` under `[ViewRules]` / the KCM checkbox) are floating overlays that come and go **together** as one layer. Meta+G (`toggleScratch`, optionally with an app id or caption to address a subset): if any scratch window is up, all hide; otherwise all come up on the output under the pointer (`canvasAt(cursorPos)`, `transfer` when they live elsewhere), at the rects they were left at, the last-used one (`m_scratchLast`) on top and focused. Run-time marks are not persisted; the rule is the durable form. A first mark offsets the default rect by 3%/4% per existing mark (`floatForScratch(w, slot)`, 5 slots) so windows do not stack exactly.
- **Layer state is derived, not stored:** `KrellisCanvas::layerShown()` = a scratch window on this canvas is not minimised or hidden. `prePaintScreen` eases `m_layerDim` toward 0/1 in 180 ms (it keeps `m_animating` up until it lands) and `paintWindow` multiplies brightness by `1 - 0.42*dim` and saturation by `1 - 0.3*dim` on every non-scratch window of that canvas. No extra quad: the dimmed windows are the backdrop.
- **Dismissal:** `KrellisEffect::scratchActivated` (the `windowActivated` hook) hides the layer when focus moves to a managed non-scratch window (click, alt-tab, `nextPanel`, ...); a dialog whose `transientFor` chain reaches a scratch window and anything the effect does not manage (panel, krunner) do not dismiss. `scratchClick` (top of `handleButton`, pressed only, never consumes the click) hides it on a press over bare canvas: no `surfaceHit`, not `overUi`, no non-desktop window frame under the point. **Escape is deliberately not bound**: the scratch windows are usually terminals that need it. `m_scratchBusy` guards the activations that showing/hiding causes itself.
- **Hiding is minimise**, so the existing hide machinery and flights apply; scratch windows stay out of `m_dockOrder`, `cyclePanel`, the bar's window count and the minimap tiles. `rulesFor` forces scratch windows floating-only (`side=stage=false`), so drops, docking and `toggleFloat` refuse them. Unmarking leaves the window floating.
- **Minimap:** footer pills "Scratchpad · show/hide (N)" (`map:scratch`) and "Mark active / Unmark" (`map:scratch-mark`) via `m_scratchAction`; state from `m_scratchState` (`count/shown/active/canMark`, in the map signature).
- **dump:** `SCRATCH count N shown 0|1 active 0|1`, `LAYER dim X`, `SCRATCHWIN <panel> shown|hidden`, `STACK <panels bottom to top>`, and a per-window `opacity`. Scenario `scratch.sh` covers mark, layer dim, outside focus and outside click dismissal, group show/hide, minimap pills and unmark.
- **Shortcut note:** Meta+G is also KWin's "Toggle Grid View"; one of the two must be freed in System Settings.
- **Not done:** persisting run-time marks, launching an app when none is marked, per-output layers (one layer, shown where the pointer is), pinning the layer so outside focus does not dismiss it. Many of Ivan's apps (Alacritty) are translucent, so overlapping scratch windows show through each other in screenshots; that is the app, not the effect.

## Floating mode leaves holes (2026-10-21)

- **Behaviour (float-first only; tiling mode still reflows).** Pulling a tiled window out into float, by drag or `toggleFloat`/`toggleDock`, does not hand its space to the neighbours: the tile is replaced by a **vacancy**, so every other tile keeps its rect. Matches the reference desktop, where tiles are the exception, not the fabric.
- **Model:** a vacancy is a docked `Panel` with `Node::vacant = true` and no views (`makeVacancy`, `isVacant`, `vacancies(root)`, `vacatePanel(doc, id)` -> nullopt for a tile with no split parent, `fillVacancy(doc, id, panel)` in `core/document`). `normalize` (tree.cpp) keeps vacant panels; **without that flag every removal anywhere pruned them**. `sanitize` still drops view-less panels, so vacancies are not restored from a saved session (the layout reflows after a restart). They are not Stage nodes because the code assumes one stage.
- **Drag** (`core/drag.cpp`): `leavesVacancy(target)` = float-first, source docked in the doc, and the target is Float or a Tab on a vacancy. Then `apply` does not collapse the source (no reflow preview) and the commit uses `vacatePanel` instead of `removePanel`. Hovering a vacancy gives a Tab target whose commit is `fillVacancy` (never a split or tab merge; `filter` checks only the Side rule and ignores `tabsAllowed`). It loses to screen-edge docks (`edgeDock`), seams and the outer frame band. Dropping a tile onto a vacancy leaves a vacancy at its own old slot (a swap with a hole).
- **Filling:** `KrellisCanvas::fillVacancyFor` is called first by `dockAtPointer` (vacancy under the cursor, else the first) and `dockAtEnd`, so a new Side window and a float docked back with `toggleFloat` take an empty slot before splitting a tile. Note float-first opens windows floating, so in practice a vacancy is filled by docking or dropping.
- **Keys:** `neighbourInDirection(..., skipVacant = true)` makes focus skip holes; `moveInDirection` passes false and a move into a hole trades places with it.
- **Rendering:** the canvas draws nothing for a vacancy (an outline was tried and rejected: the slot just stays empty). The minimap draws vacancies as an outline-only tile (`vacant` in the tile map and signature). `dump`: `VACANT <id> x,y WxH` lines, and `ORDER` lists only real tiles.
- Tests: `tests/test_keynav.cpp` (vacate/fill/survive removal/sanitize/focus vs move) and `scenarios/vacancy.sh` (tiling reflows, float-first holds, fill by dock-back, by drag, by a drag-out leaving a hole, hole survives an unrelated reflow).

- While any tracked window is fullscreen, `prePaintScreen` hides every overlay scene (bar, minimap, tile scene, drawer tabs, slot, toast, sheet, marquee): they live in KWin's overlay item above all windows. `overUi` is false then.
- Scenario `fullscreen.sh` makes a window fullscreen through a KWin script and checks the frame, that the `dump` row has no ` drawn ` field, and that the tile returns. The frame check alone passes on the unfixed code, since the frame was already output-sized; only the painting was wrong. Not verified: X11 games, pointer constraints and real input, a zoomed or off-output camera, several outputs.

## Floats can reach under a panel

- Overlay float rects are normalised to `m_area` (the maximize area, minus our bar), so a panel strut used to clamp them. `LayoutDocument::floatMargin` (`FloatMargin`, fractions of `m_area`) says how far past it a float may go. The effect sets it where `m_area` is recomputed (`krellis_effect.cpp`): full output geometry minus `m_area`, per edge.
- `clampFloat(rect, layer, margin)` honours it for Overlay; `floatPanel`, `sanitize` and native resize pass `doc.floatMargin`. `DragHost::floatMargin()` feeds the drag session (card preview and `floatRect`), and `retarget` keeps a float a float while the pointer is in the margin band (nothing docks there).
- Tiles still lay out in `m_area`; only floats overreach. Session restore uses the default clamp, so a float saved under a panel is clamped on restore.
- Test: `scenarios/float-under-panel.sh` (bottom panel strut, drag a float to the bottom edge, frame bottom > the panel's top). The harness panel is a layer-shell "Top" window, which KWin paints over the float; Plasma's real panel is a dock and sits below keep-above floats, so the screenshot shows the panel on top but the frame geometry is what is asserted.

## Edge drawers

- Resize an **edge tile** (its outer side is the root's extremity) from its inner edge until it is thinner than `m_drawerCollapsePx` (40 px) and release: it collapses into a drawer. Detection is in `resizeAt` (`NativeResize::stash`, the edge it slides out of), the conversion in `finishResize` -> `stashPanel`.
- A drawer is an ordinary overlay float (its revealed rect: the tile's size hugging the screen edge) plus canvas state `m_drawers` (`edge`, `open`). The neighbours reflow into the tile's place (the non-vacating `floatPanel` path, even in float-first). The document model and session files know nothing about drawers, so a restart restores it as a plain float.
- `floatScreen()` shifts a closed drawer so only `m_drawerStripPx` (12 px) stays in view. Everything built on it (paint, frame geometry, hit tests) follows. `updateDrawerHover` (top of `KrellisCanvas::handleMotion`) opens it while the pointer is over it (8 px slack once open) and closes it on leaving, through the normal float glide. No hover while a drag, a resize or a button is down.
- **Several drawers per edge.** Closed drawers on one edge share it: `drawerSlice(panel)` gives each an equal slice along the edge, ordered by stash order (`Drawer::seq`, first stashed at the top or left), so same-size drawers never swap. A closed drawer is painted clipped to its slice (`KrellisCanvas::paintWindow` intersects `region`), and its hover zone is sliver ∩ slice. Only one is open at a time: while one is open, other slivers do not take the pointer. Opening raises it (`raiseFloat`) and elevates it for painting (`effects->setElevatedWindow`) so it covers the other slivers; `forgetDrawer` is the only place that drops a drawer and clears the elevation (also cleared in `prepareUnload`).
- **Stash shortcut.** `Meta+Shift+X` (`KrellisStash`, D-Bus `stashActive`, `KrellisCanvas::stashActive`) turns the active window into a drawer: a tile goes through `stashPanel`, a plain overlay float is anchored to the edge and registered in `m_drawers`. The edge is the nearer of left and right, never top or bottom (panels sit there); drawers on a side stack. Focus moves on to a docked window. Pressing it on a window that already is a drawer docks it back (`forgetDrawer` + `toggleFloat`). The only tile is never stashed.
- **Tabs.** `updateDrawerTabs` shows `drawertabs.qml` (a scene over `m_area`, built like the slot) while every drawer is closed and at rest: one labelled tab (app icon from `m_tiles[panel].icon` plus the title, rotated up the left edge or down the right) per closed drawer, centred on its slice by `drawerTab()` (`m_drawerTabPx` 28 thick, at most `m_drawerTabLen` 150 long). The tab joins the sliver as that drawer's hover zone in `updateDrawerHover`. The tabs hide while one drawer is open, or flying or landing. `dump` shows `TAB <panel> at x,y WxH shown 0|1`.
- **Squeeze preview.** While an edge tile is squeezed under the collapse width (`state.stash` set in `resizeAt`), `updateMarquee` shows a drawer hint in `marquee.qml` (the `h*` properties): a tab-thick strip of the edge as long as the tile, plus a "Release to stash as a drawer" pill on its inner side. State is `m_squeezeHint`/`m_squeezeEdge`/`m_squeezeOpacity` (not `m_hint`, which is the bar's key hint); it fades when the tile is widened again or the resize ends. `dump` shows `SQUEEZE edge <n> at x,y WxH opacity o`.
- **Joined displays.** `drawerEdgeFree(edge)` is false where another output touches that edge (and overlaps it along it): no drawer is made there, because the pointer crossing over would open it. `stashPanel` refuses, `stashActive` takes the other side (or does nothing if both are joined), and `resizeAt` sets no `state.stash` or preview for a joined edge, so the tile just stops at its minimum. Test: `scenarios/drawer-outputs.sh` (needs `NEST_OUTPUTS=2`).
- **Minimap click.** A closed drawer's tile on the minimap (`map:focus:<panel>`, in `barAction`) slides it out through `setDrawerOpen(panel, true, pinned=true)`, closing any other open one first. `Drawer::pinned` keeps it out while the pointer is away at the map; `updateDrawerHover` clears the pin once the pointer has been over the drawer, and it closes as usual after that. `dump` shows `MAPTILE <panel> at x,y WxH` (screen coordinates of the tile in the map) for clicking in scenarios.
- **Minimap.** `drawerMapRect` draws a closed drawer as the sliver it leaves on screen (its slice, limited to what the window covers, at least 2.5 % thick), not the size it opens to; an open one shows full size. The map signature includes the drawn rect, so it refreshes when a drawer opens or closes.
- **Resizing a drawer.** An open drawer takes the ordinary float native resize; on commit `finishResize` re-anchors it to its edge (outer side pinned to the screen edge) instead of remembering a free float. Its new size is what it slides out to next time.
- Grabbing a drawer (`startDrag`) turns it into a plain float; `relayout` prunes entries whose panel is no longer a float. `dump` shows `DRAWER <panel> edge <n> open|closed at x,y WxH`.
- Not done: no re-dock-by-resize (drag it to a screen edge to dock it again), no way to reorder drawers (they keep stash order), no settings keys for the two sizes, not persisted.
- Tests: `scenarios/drawer-preview.sh` (squeeze preview, minimap click opens and pins a drawer), `scenarios/drawer-tabs.sh` (a tab per drawer, hovering a tab opens that drawer), `scenarios/drawer-stash.sh` (the shortcut, restore, minimap screenshot), `scenarios/drawer-stack.sh` (two drawers on one edge, per-slice hover, one open at a time, widen an open one), `scenarios/drawer.sh` (overview, squeeze the right-most tile with `simNativeResizeStart/Move/End`, hover with `simMotion`).

## Flip stacked / side by side
- **Core.** `flipBoundary(root, splitId, index, wrapperId)` (`core/tree.cpp`): a split of exactly two has its axis toggled in place; in a longer one the pair either side of the boundary is wrapped in a new split of the other axis, so only that pair turns and the rest keep their sizes. Flipping the wrapper again dissolves it (`normalize` flattens it into the parent). `flipPanel(doc, panel)` (`core/document.cpp`) picks the panel and its next sibling (the previous for the last one). When the sibling is itself a split of the new axis, `normalize` merges it (three stacked rather than a column inside a column). Tests in `tests/test_tree.cpp`.
- **Key.** `Meta+Shift+T` (`KrellisFlip`, D-Bus `flipActive`, `KrellisCanvas::flipActive`) flips the active docked window with its neighbour; pressing it again flips back. The first sibling stays first (left/top). Floats and drawers are ignored. It animates through the ordinary `relayout(true)` glide.
- **Mouse.** Middle-click on the gap between two tiles flips that pair (`KrellisCanvas::seamAt` finds the split and index from `m_rects`; reach is the gap plus 2 px, so a click on a window is left alone). The release is swallowed too (`m_swallowMiddle`). `simMiddleButton x y press` is the test hook. Zoomed or in overview, the seams follow the camera.
- Test: `scenarios/flip-split.sh`.

## Navigation rules

- **`Navigator::reveal(id, preferWiden=false)`** replaced `ensureVisible`. A target outside the frame slides the frame the minimum distance per axis at the same size (stretching only on an axis where the target is longer than the frame) and re-frames the leaves inside with `record=false`, so history isn't flooded. Only `windowAdded` passes `preferWiden`: a new neighbour widens the frame to include both when the result stays within `WIDEN_LIMIT` (2.2) times the current area, else it slides. Used by activation, spawn, move, restore, flip, `focusDirection` and `cyclePanel`. `slideTo` uses `m_entries` rects, never mix them with `frameLeaves`/`focusLayout` rects (no metrics).
- **Close redistribution:** `closeView` calls `detachView(..., true)`, so a closed window's share goes back to every sibling in proportion (`removeNode(..., keepProportions)`). Hide, restore and `floatPanel` still absorb into the next sibling, because `restoreTargetFor` records `share = own/(own+nb)`. The cross-canvas transfer in `multicanvas.cpp` goes through `closeView` too and follows the new rule.
- **Zoom rubber band:** `bandedFactor` in `core/navigator.cpp` damps only zoom, never pans, in log space with a hard bound of `ZOOM_OVERSHOOT` (0.12 in ln units) past the zoom limits. The band keeps raw-coordinate state, so pulling back retraces the curve. `finishGesture` springs back through `focus(bestFit)` + `retarget()`. `m_minTile` (minimum tile size, recomputed in `sync()`) feeds the zoom-in limit (`* 0.65`).
- **Dropped (E3):** a float's initial size still comes from the fixed `{0.2.., 0.15.., 0.6, 0.65}` rect. `w->frameGeometry()` at `windowAdded` is KWin's placeholder (1000x718 for every window in the nested harness), not the client's size, so sizing from the client needs the first commit instead.
- **Open (E4):** `dockAtPointer` samples `effects->cursorPos()` in `windowAdded`. Whether the cursor moves between the window being announced and being drawn is unverified on the real compositor; the nested harness can't show it.

- **Theme.** `effect/theme.{h,cpp}` + `theme_tokens.h` derive the overlay colours from the Plasma scheme (KConfigWatcher on kdeglobals) when `followTheme` is on; QML only uses `theme.*` tokens (`tests/check_qml_colors.sh` enforces it). - **Undo/redo.** `core/history.h` (`History`, `sameLayout`, 50 entries, 600 ms coalescing by key) and `core/reconcile.h` (applies a snapshot onto the live document without resurrecting closed windows or touching minimize state). Canvas side: RAII `EditScope(canvas, label, key)` around every layout edit (`moveDirection`, `resizeStep`, `flipActive`, middle-click flip, `endDrag`, `stashPanel`, `toggleFloat`/`toggleDock`), and `commitEdit` in `finishResize`. Keys: Meta+Alt+Z / Meta+Alt+Shift+Z; `dump` shows `HISTORY undo N redo M`.
- **Fly-to.** `NavigationHost::flyTo()/clockMs()`, `Navigator::tick` (called next to `m_camera.step`), `flying()` keeps `m_animating` on. Settings reach canvases through `KrellisEffect::m_toastsOn/m_flyToOn`, which `makeCanvases` and `applySettings` both copy: a setting that only `applySettings` copies is silently default on a canvas created later (this bit `flyTo`).
- **Frame cost.** Toast and sheet only hold the frame clock while they fade or slide (`m_toastBusy`, `m_sheetBusy`); the toast hold waits on a real-time `QTimer` (the animation clock moves at most one frame per tick, so it cannot time a pause). Keep new overlays idle once settled.
- **Which-key.** `core/chord_hint.h` state machine; `KrellisEffect::trackChord(event)` runs first in `handleKey` and re-reads the modifier mask from each event (`simKey` fakes one via `m_simMods`); a precise `QTimer` shows `whichkey.qml` (rows from `effect/shortcut_help.h`, chords from KGlobalAccel) via `KrellisCanvas::showSheet/hideSheet`. - **Safe mode.** `effect/boot_guard.cpp` + `core/safemode.h`: marker `$XDG_STATE_HOME/krellis/boot.json`; two early deaths (< 120 s each, within 10 min) make the factory refuse to load and send one `notify-send`. `tools/live.sh reset` (or `on`) clears it; `status` reports it. Harness: `NEST_BOOT_STRIKES=N` seeds the marker; the harness wipes its own state dir, never Ivan's.

**Tiny windows (2026-10-21).** Two changes so deep subdivision stays usable. (1) `[General] iconBelow` (default **0** = always live since 2026-10-22; set e.g. 160 for the icon swap; KCM "Tiny windows"): `iconTile(rect, below)` shows the app icon when a tile is narrower than `below` px or shorter than 40% of it. (2) `restRect` no longer floors width and height separately: a tile under the client's floor (the rule's minimum, raised to the client's own `Window::minSize()` via `clientMinimum`) is asked for the whole tile scaled up evenly (capped at `MaxHeldSide` = 8192 px), and the paint transform shrinks it back, so contents keep their proportions and fill the tile (Brave held at 540 px used to be drawn letterboxed at 0.57 scale). The client minimum deliberately does not feed `minSize()` for the layout: that pinned every neighbour at its minimum and froze divider drags (`resize.sh` caught it). Scenario `tiny-live.sh` (seed `tiny-live.rc`; `EXPECT=icon` without the rc for the default). `previewsize.sh` fails identically before this change (checked against the previous commit); `land-anim.sh` needs a `glide=false` rc.

**Tile minimum (2026-10-21).** The real limit on spiral depth was the hardcoded 320x200 layout minimum for apps without a rule (`KrellisCanvas::minSize`), not any app's own size: below ~320x200 per tile `layoutWithMinimums` stops following the weights and scales every tile to the same size, so a spiral stops halving after ~3 levels. It is now `[General] tileMinWidth` / `tileMinHeight` (default **1**, KCM "Smallest tile"; 320x200 restores the old floor). Apps with a `[ViewRules]` entry keep their own `minWidth`/`minHeight` (default 160x120). With 1 px, a 12-window spiral on 1440x2530 shrinks 708 -> 348 -> 168 -> 78 -> 33 -> 10 px wide; pair it with `iconBelow=0` to keep such tiles live. Scenario `deep-spiral.sh` (`EXPECT=floor` + `deep-spiral.rc` for the opt-in floor).

**Focus on close (2026-10-22).** `[General] closeFocus` (default true, KCM "Closing a window"): when the focused docked window closes, focus goes to its neighbour in the layout instead of KWin's most-recently-used pick. `closeFocusPanel` (core/document.cpp) takes the previous sibling in the parent split, else the next; a sibling group yields the leaf nearest the gap, vacancies are skipped, and a panel that keeps other tabs or is not docked yields nothing. `KrellisCanvas::windowClosed` decides before `closeView` and activates one event-loop turn later, because KWin picks its own successor after the `windowClosed` signal. Scenario `close-focus.sh` (rc `close-focus.rc` with `EXPECT=off` shows KWin's own choice).

## Tabbed tiles (2026-10-22)

- **Switchable** (`[General] tabs`, default `true` since 2026-10-22; it was opt-in at first; `tabs.rc` sets it explicitly, `off` runs use `tabs=false`). Core support is in `core/document.{h,cpp}` (`splitOut`, `untabView`, `tabInto`, `untabAll`) and in `DragSession` (tab tear-out on its own copy of the document, `m_pdoc`). The effect side is `effect/tabs.cpp` plus `tabstrips.qml`.
- **Model.** `m_windows` holds only the *shown* window of each panel, so every existing `t.panel` lookup still works. `m_stowed` holds the other tabs: same rest rect, never painted (`behindTab`), never hit-tested. `syncTabs()` runs first in `relayout` and reseats windows to whatever the document says (panel, selected tab); `selectTab` only edits the document. `belowTabs()`/`tabInset()` reserve a `TAB_H` (28 px, at most 25% of the tile) strip at the top of a tabbed tile, and `restRect`, `shownRect`, `awaitingLanding` and the flights use them. Anything that loops `m_windows` and means "every window" must also loop `m_stowed` (`owner`, output removal, `detachWindow`, `transfer`, `applyRest`, `writeSession`).
- **Strips** are an overlay scene (`tabstrips.qml`, theme tokens only). All pointer handling goes through `tabAt()`, `tabButton` and `tabMotion` in `tabs.cpp`: click selects, middle click closes, a press then a move past the drag threshold tears the tab out (`startDrag(window, pos, viewId)`), dropping a tile on the middle of another tiles it as a tab (the core's `Kind::Tab`; `tabsAllowed()` returns `m_tabsOn`, so with tabs off the middle of a tile does nothing).
- **Where a drop tabs (2026-10-22, changed after Ivan disliked the middle).** Only the title-bar band tabs a docked tile or float: `DragHost::tabDropHeight(panel)` (core default = `tabbarHeight`; the effect returns `min(TAB_H, 25% of the tile)` for every tile, tabbed or not) feeds `DragSession::tabTarget`, and the effect's `bodyTabs()` is `false`, so the body of a tile has no target (the core default `true` keeps the upstream centre-tabs and its tests). Vacant slots still take a window whole. The band wins over the top split edge: the top split zone starts right under the band (Ivan wanted both; removing the split zone was tried and rejected). Pausing in that zone on the way to the band previews the split. Dragging by the bare part of a strip: `TabPress::bar`, a press that hits no tab picks the view on show, a click there does nothing.
- **Shortcuts, registered only while `tabs` is on** (`syncTabShortcuts`, like pin): Meta+PageDown / Meta+PageUp (next / previous tab), Meta+Shift+U (split the tab out), Meta+Ctrl+Shift+arrows (group into the neighbour that way). Ids `KrellisNextTab`, `KrellisPreviousTab`, `KrellisSplitTab`, `KrellisGroupLeft/Right/Up/Down`. `helpGroups()` skips rows whose action isn't registered. D-Bus: `nextTab`, `previousTab`, `splitTab`, `groupLeft/Right/Up/Down`.
- **Switching it off** runs `untabAll` under one undo step. **Sessions** do not save tabs: `writeSession` flattens the document (the file format is one view per panel) and maps stowed windows to their new panels, so every window comes back in its own tile.
- **Bug found by the scenario:** `DragSession::end` used the host's document, which for the effect never saw the tab leave its panel, so the torn-out window ended up in two panels. `end` now detaches it again from `base` (idempotent).
- **Known limits:** no strip under an overlay float; no drag-to-reorder inside a strip; cancelling a tear-out leaves the neighbour tab selected; moving a tabbed window to another output splits it from its group; a strip still lists a tab that is in the pointer's hand.
- Scenario: `scenarios/tabs.sh` with `tabs.rc` (32 checks; with `tabs=false` most of them fail, which is the point; also checked by mutation: `bodyTabs()` true fails the middle-drop checks, no bar drag fails the bare-strip checks).
