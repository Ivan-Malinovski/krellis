# Changelog

## Unreleased

- **`tools/healthcheck.sh`**: a read-only PASS/FAIL for the silent failure mode behind a Plasma upgrade — the effect stops loading while `kwinrc` still says it is enabled, so the desktop quietly loses tiling, its bar and its shortcuts. Reports whether Krellis is loaded, whether the running build is the newest installed one, whether it was built for the installed KWin, and whether `kwinrc` enables it, each with the fixing command. `--quiet` and `--notify` for autostart use.
- **Installer fixes.** `--pacman-hook=rebuild` installed through `pkexec`/`sudo` used to record `root` and root's sanitised `PATH`, so the hook would have rebuilt as root and missed user-installed `cmake`/`ninja`; it now records the invoking user and that user's login `PATH`. Installs also remove superseded `krellis*.so`/`trellis*.so` files, and `--check` gained `advisory:` lines for kwinrc entries whose plugin is missing or was built for another KWin (its exit code is unchanged).
- The nested test harness refuses to run while a stray `kwin_wayland --virtual` owns `org.kde.KWin` on the session bus, which otherwise silently kills every global shortcut in the real session and makes logout do nothing.
- The optional Aurorae decoration helper (`tools/build-aurorae-fix.sh`) now pins 6.8.2 as well as 6.7.5 (the render-cache patch applies unchanged to both). A one-line upstream KWin patch that would let effects use `KWin::SpringMotion` without a local ABI declaration is in `patches/`.

- **The lone-window share follows the display's long axis.** On a monitor used on its side, `loneWidth=70` used to take 70% of the *width* — 1008 of 1440 pixels on a 1440x2560 screen — which left a tall sliver with gutters down both edges. The share is a reading width, so it now takes rows on a turned output and columns on a wide one: 1440x1792 centred instead of 1008x2560. The landscape behaviour is unchanged, a second window still restores the usual split (stacked on a turned output, which splits down its short side), and box drawing is untouched. New scenario `lone-width-portrait` runs the nested compositor at 800x1280.
- **The settings module was tidied up.** Every explanation now sits under the control it explains (one of them, about floating windows, sat four rows below its checkbox), the page is grouped as Windows, Zoomed view, Extras, Motion and Appearance and help instead of hiding the minimap, scratchpad and tabs inside "Zoomed view", every number can be typed instead of clicked up in steps, and the spin boxes carry their unit. In System Settings' narrower page the explanations are now wrapped to the page: they used to run off the right edge, because a wrapped label reports its whole text as its implicit width and the form grew past the window. A rule can be added by clicking **Pick a window…** and then the window — the same interactive selection KDE's window rules use — instead of typing a desktop file by hand; rules gained the floating size and "open at the pointer" fields the file has always had, the per-rule lone width is editable, a rule with none of its three placements on now says so, and the remove button no longer renders its own label when the icon is missing. New scenario `kcm` loads the module in the nested compositor and fails on any QML error.
- **A window alone on the canvas can take a reading width.** `[General] loneWidth=70` (or a rule's `loneWidth`) shows a single tile centred at 70% of the screen instead of filling it, which is what makes a browser usable on a 3440 px ultrawide. The camera is widened around the tile, so the client is really that size rather than scaled down. A second window brings the usual split back; `-1` in a rule follows the general setting and `0` means full width. Settings module field, and a scenario `lone-width`.
- **A hidden window that wants attention makes its drawer's tab blink.** Stashing a window (Meta+Shift+X) leaves a labelled tab on the edge, and that tab now pulses with the accent while the window demands attention, so a build that finished or a chat that needs an answer is visible without opening the drawer. It stops when the window is activated, when the drawer opens, or when urgent handling is off. Scenario `drawer-urgent`.
- **KWin 6.8 (Plasma 6.8) support.** Ported to KWin 6.8's paint API, where the paint hooks report whether the frame rendered successfully; without the port the effect stops loading after a Plasma update. The camera and tile fades now run on KWin's own spring instead of a local integrator, with the same stiffness and damping, so motion is unchanged. This targets KWin 6.8: Plasma 6.7 stays on the v0.0.2 release. See [the 6.8 notes](README.md#kwin-68).
- Added `tools/live.sh login` for startup automation: it waits for KWin and retains the crash-loop marker when loading the newest installed build.

- Added a depth-verified zoom-out diagnostic with persistent D-Bus latency measurement and generated terminal text. Documented an optional, separately licensed Aurorae 6.7.5 patch for long main-thread SVG cache compression pauses; the decoration artwork and transparency stay unchanged.
- Overview labels retain their rendering scene while hidden, avoiding repeated QML/graphics setup when zooming back out. Labels, outlines and window presentation keep their existing appearance. Added shared-instance Kitty stress coverage (`overlay-reuse`).
- Bounded forced backdrop blur for deep zooms. The Hyprland profile suspends blur during camera presentation and held gestures, restoring it at rest; tiny and oversized tiles skip it. Transparent contents remain visible, with a temporarily sharper backdrop. This avoids repeatedly allocating huge or zero-sized KWin blur targets. Added a repeated-zoom fixture with 25 transparent, blurred Kitty clients (`zoom-depth`).
- Hyprland-profile camera navigation requests destination sizes once for visible content tiles at the start of a discrete zoom, then animates available buffers. Continuous gestures wait until release. Offscreen, icon-only and background-tab buffers are retained; offscreen painting skips transformed bounds including shadows. Camera presentation uses direct per-axis fitting, so vertical-only zoom does not magnify the width or crop the right edge. Layout edits and native border resizing keep their existing behavior.
- Reduced repeated window searches and geometry calculations during zooming. Offscreen and unreadable overview labels skip clipping and QML updates; the minimap builds tile rows only when they change. Added an isolated many-window timing fixture (`zoom-load`).
- Fixed the dragged card trailing far from the pointer after a window is torn out of another (a browser detaching a tab): the new window is moved before it is under the pointer, so the card kept that distance. It is now held by the middle of its title bar. Scenario `tearoff`.
- Fixed a window moved to an output of the other orientation being stretched while its client catches up, with `animationProfile=hyprland`: for three seconds after the move it keeps its own aspect. Scenario `cross-aspect`.
- **Size and spot for new floats, per app.** `[ViewRules]` takes `floatWidth`, `floatHeight` (pixels; 0 keeps the window's own size on that axis) and `floatAtPointer` (the float's top-left corner opens at the pointer, kept on the screen). Without them a float still opens at 60% × 65% of the screen. The README's Emoji Selector rule uses them so it opens small at the pointer. `scenarios/emoji-place.sh`.
- **Dwindle and "beside focused" follow what is on screen.** If the focused window is out of view, a new window splits the tile you last used among those visible, instead of opening next to the hidden one. It also picks right or below from the tile's shape on screen, so a window that fills the screen gets its neighbour beside it even when hidden columns make it narrow in the layout.
- **Cogwheel on the minimap.** It opens a small settings panel with switches for the settings you flip most: new windows open at the pointer (off means the placement you last chose, dwindle at first), flagging windows that need attention, focusing the neighbour on close, shake to float, and toasts. "All settings…" opens the full module. Changes are written to krellisrc and apply at once. D-Bus `toggleSpawnPointer`.
- **Urgent windows.** A window that is not active and demands attention (KWin's flag: a denied focus request, a chat or build notification) gets a steady amber outline on its tile, an amber tile (and a lit edge tab) on the minimap, first place in the Meta+/ palette marked "needs attention", and a toast. Meta+U (`focusUrgent`) jumps to the most recently used one, or says nothing needs attention. KWin clears the flag on activation, so the cue ends by itself. Setting `urgent` (default on; settings module: "Attention"); a stowed tab counts toward its tile's marker but has no tab-strip marker.
- **Dwindle spawning.** With the pointer placement off, `spawnTarget=dwindle` (settings: "Halving the focused tile") opens each new window by halving the focused tile along its longer side, as Hyprland's dwindle layout does. Unlike `focused`, which adds a column to the focused tile's row and shrinks every sibling, only the focused tile gives up space; the other tiles keep their sizes.
- **Dwindle follows the pointer and closes like Hyprland.** With `spawnTarget=dwindle` the new window now takes the half of the focused tile the pointer is in (a pointer outside the tile counts as the nearer half). Setting `dwindleSide=after` (KCM: "Dwindle puts the new window") restores right-of / below. Dwindle splits also stay nested, so closing a window gives its split-sibling the whole pair's share and the rest of the row keeps its size; before, the freed share went to the next tile in the row. Layouts saved by the session store keep the grouping.
- **Shake a window to float it.** While dragging a tiled window by its title bar, swing the pointer back and forth (four quick turns of at least 80 px within 0.6 s, along either axis) and it comes out of the layout as a float, exactly as if Shift were held; it stays that way until you drop it. Plain drags and slow wiggles are unaffected. Turn it off with `shakeFloat=false` or in the settings module ("Dragging a window"). It does nothing in floating-first mode, where drags float already.
- Fixed a brief full-size flash of a window right after its minimize animation, and of an edge tile squeezed toward a drawer: a window with no rectangle to show is no longer painted untransformed.
- Fixed a closed window flashing at full size for one frame right after its fade-out (Alt+F4, floating or tiled; most visible with Dolphin). Once the close animation ended, nothing owned the still-alive window any more, so it was handed on to be drawn natively. Also, the effect now claims the close, so KWin's Scale effect no longer runs its own, shorter animation on the same window.

- Reduced animation work: each output advances its own canvas; ordinary repaint requests address that output's render views directly. Cross-output flights still repaint both sides and clear their final pixels. The Hyprland profile no longer scans native geometry on every animation frame or on unchanged drag-timer ticks. Animation curves and durations are unchanged. Added two-output work counters and real-frame surface-damage coverage.
- Documented a float-only application rule for KDE's Emoji Selector, including placement permissions that prevent accidental docking.

- Added an optional **Hyprland** animation profile in settings (`animationProfile=hyprland`), using Hyprland 0.54's Bézier preset: 479 ms movement, 410 ms opening, 149 ms closing, and independent 173/146 ms fades. Opening/closing styles are 87% pop-in, slide, and vertical collapse (`windowAnimation=popin|slide|gnomed`). Applications resize only for new destinations; painting animates their available buffers. The profile overrides resize glides, landing timing and camera flights. Retargeting starts from the current painted rectangle without restarting the opacity clock. Existing defaults are unchanged; workspace effects and newer Hyprland springs are outside this profile.

- Held move shortcuts now step immediately, pause for 320 ms, then repeat every 150 ms with a persistent outline on the moving tile. Release, focus changes and other key presses stop the repeat; duplicate system repeat notifications do not accelerate it. Custom shortcut bindings use the same behavior.

- Fixed repeated resize requests during static drag previews when a Wayland client rounded a fractional tile size. A rounded result within one pixel no longer causes Krellis to resend the identical request every frame.

- Dragged windows gain an animated shadow and accent outline. Landing feedback fades in 180 ms; optional layout glides settle drops in 240 ms; open drop slots morph from their current position when the target changes. Body-half selection tolerates small pointer movements near a boundary. Lift, landing, undo and moving drop highlights animate with `glide` off, without continuously resizing apps. `landMs=0` together with `glide=false` makes decoration feedback immediate.
- Interrupted layout glides preserve their velocity and turn smoothly toward the new arrangement. Undo/redo briefly highlights the windows it moves (220 ms); with `glide` on, floating transitions also animate.
- Zooming out reveals app icons and title labels on small tiles, plus named boundaries for saved views. Labels follow the painted geometry and are clipped behind covering windows.
- With `flyTo=true` and `glide=true`, distant jumps use a continuous, shallow camera arc rather than zooming out to encompass the entire journey. Nearby jumps remain direct.

- Dropping on a window now splits only that tile into halves, including drops deep inside its body. Dropping in the gap between tiles still shares space across the row or column. The title strip still accepts tabs.
- Fixed: a window floated with Shift and dragged to another monitor could vanish from Krellis (never tiled again until it was closed and reopened). Handing a window to another monitor judged it a second time, and a floating window that KWin briefly reports as undecorated looked like an always-on-top overlay. Windows that are already managed are no longer re-judged when they move between monitors.
- Pressing Shift in the middle of a drag now floats the window straight away, without moving the pointer (and releasing it undoes that). Before, the key was only noticed on the next pointer motion, so pressing it while holding still seemed to do nothing.
- **Scroll on the gap between two tiles to zoom**, with no key held and whatever the windows are (Brave and other apps that draw their own title bar included). Scroll in narrows the frame toward the tile on the right or lower side of the gap, scroll out widens it; hold Shift to favour the left or upper tile instead. Scrolling over a window is still left to the app.
- Small helper windows no longer take a tile or get resized: fixed-size windows (password and polkit prompts such as the one `pkexec` shows, the wallet prompt), windows with a parent or that skip the taskbar, and undecorated always-on-top or thin strips (screen-sharing "you are sharing" bars) keep their own size and place. Decided from how the window asks to be shown, not from its name; a small, ordinary, resizable window still tiles. The journal line `leaving alone <app> <title> <reason>` says why.
- Plasma's own windows (the panel edit toolbar and panel settings, the widget explorer) are never tiled, so editing panels no longer fights the layout.
- Windows keep KWin's background blur. Krellis draws every tile transformed, which made KWin's blur effect skip them; tiles now carry the force-blur flag, so translucent windows (Kvantum, Kitty, Dolphin) blur what is behind them again.
- **Survives KWin upgrades.** The plugin records the KWin it was built for and refuses to load into any other, logging why and sending one notification, instead of crashing the compositor on a changed private ABI. `KRELLIS_ALLOW_KWIN_MISMATCH=1` overrides that.
- `./install.sh --check` says whether the installed plugin matches the installed KWin. `--build-only` and `--install-only` split building from installing. The installer now removes the old plugin file before installing, so a running KWin never has a mapped file overwritten under it.
- `./install.sh --pacman-hook[=warn|rebuild]` (Arch and derivatives) installs a hook that runs after pacman upgrades `kwin`: `warn` prints what to do, `rebuild` rebuilds from your checkout as your user and installs it. `--no-pacman-hook` removes it.

- **Quick jump (Meta+/).** A palette over your windows and saved views: type part of a title or app name (`ff docs`, `term`), Up/Down or Tab to choose, Return to fly the camera there and focus it. Hidden, scratchpad and drawer windows are brought back; windows on other monitors are listed too. Empty query plus Return returns to the previous window. Esc, a click outside, or the shortcut again closes it. Rebind it in System Settings → Shortcuts ("Krellis: Quick Jump").
- **Pin (Meta+Shift+P), off by default.** Turn it on with the Pin checkbox in the settings module or `pin=true`. A pinned tile keeps its place in the layout, and while it is out of view its window is drawn live as a thumbnail in the bottom-left corner. Click the thumbnail to go to the tile; press the shortcut again to unpin. Pins are not saved across sessions, and floating windows cannot be pinned (they already stay on screen).
- A stashed (edge-drawer) window that something outside Krellis activates, such as the start menu, a launcher or the app itself, now slides out instead of staying off screen. Activating a tile that is out of view already brought it into view.
- **Tabbed tiles (Meta+PageUp/PageDown), on by default.** Turn them off with the Tabbed tiles checkbox in the settings module or `tabs=false`. Several windows can share one tile: drop a window on the title bar of a tile (its top strip; the body splits the tile), or press Meta+Ctrl+Shift+arrow to group the focused window into its neighbour. A tab strip appears along the top; click a tab to show it, middle-click to close it, drag it out to give it a tile of its own (or Meta+Shift+U). The bare part of the strip drags the tab on show, like a title bar. Meta+PageDown / Meta+PageUp cycle the tabs. Turning `tabs` off splits every tabbed tile back into separate tiles. Tabs are not saved across sessions, and a tile under an overlay float shows no strip.

## 0.0.2

- A tiled window that goes fullscreen (a Brave video, a game) now covers the whole output instead of being scaled into its tile, gets native input, and returns to its tile afterwards. The overlays (bar, minimap, toasts) are hidden while a window is fullscreen.

## 0.0.1

First tagged release.

- Tiled layout on an infinite canvas with a spring-driven camera, one canvas per monitor.
- Drag docking, floating windows, floating-first mode, edge drawers, an opt-in scratchpad, minimap, saved views, undo and redo.
- Keyboard movement (Meta+arrows or Meta+A/S/D/F) and focus (Meta+Ctrl+arrows), with hand-over to the next monitor and a 20% shrink at a dead end.
- Session restore, per-application rules, Plasma theme following, and a settings module.
- `install.sh` builds and installs the effect and the settings module; `--uninstall` removes them.
